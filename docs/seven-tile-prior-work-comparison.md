# 1・4・7枚の待ち形: T001〜T026との対照

比較対象は、firedial氏のZenn本
「[麻雀の多面待ちのパターンを全て求めてみた](https://zenn.dev/firedial/books/mahjang-waiting)」
の第9章「[待ち牌パターンリスト(7枚以下)](https://zenn.dev/firedial/books/mahjang-waiting/viewer/result_tile_7)」である。
公開表に掲載された正規形は、1枚形1件、4枚形6件、7枚形19件の計26件（T001〜T026）である。

## 結論

公開画像から転記した26個の代表牌姿について、本リポジトリの通常形待ちを再計算したところ、
待ち牌集合は全件で公開表と一致した。したがって、T001〜T026はすべて本リポジトリの手法でも
聴牌形として解析できる。

一方、現行の集計キー `waitDecompositionCodes` だけでは26件を完全には分離できない。
T018とT026はいずれも `[255, 255, 273, 442]` となり、代表牌姿26件は25分類になる。
これはコード列が待ち牌の具体的な位置と待ち核部品の位置関係を捨て、部品種別の多重集合だけを
保持するためである。

既存の待ち核集合を平行移動・左右反転について正規化し、次の比較用キーを使うと26件はすべて
異なる分類になる。

```text
(waitDecompositionCodes, normalizedWaitCores)
```

さらに、各代表牌姿を1〜9の範囲で平行移動・左右反転した全配置を比較すると、Zenn側の26分類は
この比較用キーでは47分類に細分化され、異なるT番号間の衝突はない。したがって、この比較用キーは
T001〜T026に対して真に細かい分類である。ただし、これは比較実験用のキーであり、公開APIの
`classificationId` は引き続き `waitDecompositionCodes` に基づく。

ため区別できる。

## 集計方法と再現

比較スクリプトは、公開表の画像から転記した代表牌姿について次を行う。

1. 1枚、4枚、7枚の内訳がそれぞれ1、6、19件であることを確認する。
2. 各代表牌姿の待ちを再計算し、公開表から転記した待ちと比較する。
3. 各牌姿を1〜9内で平行移動し、左右反転した全配置を生成する。
4. 現行の `waitDecompositionCodes` と、正規化待ち核を併記した比較用キーを集計する。
5. 現行キーでは44個のT番号内分類が42個のコード列になり、T018とT026の間で2コードが
   共有されることを確認する。
6. 比較用キーでは47個のT番号内分類が47個の異なるキーになり、異なるT番号間で
   衝突しないことを確認する。

```bash
PYTHONPATH=examples python3 examples/zenn_wait_pattern_comparison.py
PYTHONPATH=examples python3 -m unittest examples/test_zenn_wait_pattern_comparison.py
```

## 比較上の制約

- Zenn側は同じ牌を5枚以上使う形も許すが、T001〜T026の掲載代表はすべて4枚以下なので、
  今回の代表牌姿照合には影響しない。
- Zenn側の一覧全体には非正規形もあるが、T001〜T026は1・4・7枚の正規形だけを対象にした。
- 本リポジトリの全牌種・全牌姿の既約分類数（1枚1分類、4枚11分類、7枚49分類）と、
  単一スートの表示形26行は集計単位が異なる。今回比較したのはT番号の代表と、その
  平行移動・左右反転配置である。
